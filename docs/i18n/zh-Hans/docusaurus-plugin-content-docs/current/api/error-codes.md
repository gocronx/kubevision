# 错误码

大多数 JSON API 使用 HTTP `200`，并在统一响应结构中返回业务码。健康检查和
WebSocket 握手错误使用常规 HTTP 状态码，因此客户端需要同时处理这两层状态。

| 错误码 | 含义 |
|--------|------|
| `0` | 成功 |
| `40001` | 缺少必需参数 |
| `40002` | 参数或请求体无效 |
| `40100` | 未认证或认证无效 |
| `40101` | 令牌已过期 |
| `40102` | 需要双因素验证 |
| `40103` | 双因素验证失败 |
| `40300` | 授权策略禁止操作 |
| `40400` | 记录或 Kubernetes 资源不存在 |
| `40900` | 资源已存在、版本冲突或并发操作冲突 |
| `42200` | 校验或 Kubernetes Dry Run 失败 |
| `50000` | 服务内部错误 |
| `50200` | Kubernetes 集群不可用 |

错误消息用于补充上下文，不是稳定的机器接口。程序应根据 `code` 分支；报告内部
错误时应附带响应元数据或响应头中的请求 ID。

不要盲目重试校验、认证或授权错误。服务端和集群临时故障应采用有上限的退避，
版本冲突则应重新读取资源后再重试。
